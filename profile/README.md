<h2>一、搭建指的是哪一端</h2>
<p>这里说的服务器，是自己控制的一台中转机，负责把本地流量转发到上游住宅地址。</p>
<p>它不是住宅地址本身。住宅地址来自上游服务商，服务器只做转发和鉴权，两者是配合关系。</p>
<p>自建的好处是可控、能加规则，坏处是要自己维护，出问题没人兜底。</p>
<h2>二、服务器与线路怎么选</h2>
<p>配置不用高，一核一 G 足够跑几十个并发，瓶颈在带宽和线路，不在 CPU。</p>
<p>机房位置影响延迟，做美国业务就选美西或美东，别绕欧洲一圈再加一跳到美洲。</p>
<p>带宽按并发估，单个后台会话峰值几百 Kbps，十个人同时用，十兆起步比较稳。</p>
<h2>三、协议怎么选</h2>
<p>HTTP 代理兼容性最好，配置简单，但不加密，适合已有加密通道的情况。</p>
<p>SOCKS5 支持 TCP 和 UDP，适配面广，配合认证能直接给浏览器用。</p>
<p>需要加密时走隧道方案，把代理流量套在加密通道里，代价是多一层开销。</p>

<h2>四、账号与端口怎么配</h2>
<p>不要用默认端口，改成一千以上不常用的端口，减少被扫描到的概率。</p>
<p>认证用独立账号，一个使用者一个，方便出问题时单独停用而不影响别人。</p>
<p>把并发数和连接时长写进配置，防止单个账号占满资源。</p>
<h3>防火墙只放行必要端口</h3>
<p>系统防火墙只开代理端口和 SSH，SSH 改密钥登录并禁用密码，减少暴力尝试。</p>
<h3>日志要留多久</h3>
<p>七天足够日常排查，留太久占磁盘，还要注意日志里别记录明文认证信息。</p>
<h2>五、系统层怎么调</h2>
<p>调大文件描述符上限，代理服务吃连接数，默认值往往不够用。</p>
<p>开连接复用，降低握手开销，长连接场景提升明显。</p>
<p>关闭不必要的服务，减少攻击面，改动前先记下原状态便于还原。</p>
<h2>六、上线后的监控</h2>
<p>监控三件事：在线连接数、出口带宽、上游地址可用性。</p>
<p>上游地址失效时要有告警，能自动切换的做切换，不能切换的手动处理。</p>
<p>每周看一次日志，异常的登录来源和异常流量要能及时发现。</p>
<p>监控之外还要留一份配置备份，包含代理服务配置、防火墙规则和账号清单，重装机器时照着恢复，比临时摸索省事得多。</p>

<h2>常见问答</h2>
<h3>自建服务器能代替住宅IP吗？</h3>
<p>答：不能。服务器拿到的通常是机房地址，住宅地址要向上游服务商购买，服务器只负责把流量转发过去，两者是配合关系。</p>
<h3>一台服务器能带多少条上游线路？</h3>
<p>答：取决于并发和带宽，不在软件上限。实际部署中一核一 G 的机器带几十条上游、几十个并发是常见规模，再多要看带宽和连接数。</p>
<h3>为什么搭好之后速度比直连还慢？</h3>
<p>答：多了一跳中转，延迟必然增加。若慢得明显，先看服务器到上游的线路质量，再看是否开了加密封装，最后排查带宽是否被打满。</p>
<h3>服务器需要用域名吗？</h3>
<p>答：用 IP 直连不需要域名。若用域名访问，按服务器所在地的规定处理，境外服务器通常不涉及国内备案，但仍要遵守当地法律。</p>
